## 2026-11-11: success event `episode_completed`; the Spark unit counts as `week_opened`
The kill criteria count `episode_completed` (a viewer reaches an episode's final 30 seconds), so it is contract.yaml's success_event, in config.ts, CHARTER.md and `reportCoreSuccess()`. Spark cannot serve an episode, and counting a week-page read as an episode completion would make the kill count lie. So `reportCoreSuccess()` is wired only to the episode player hook (`watchEpisode`, any `video[data-episode]`, fired once at duration minus 30 s); no page has one yet, so the count stays at zero until the first episode airs. The Spark unit, `/e/32` read to its source ledger, sends a second allowed client event, `week_opened`, when `#ledger-end` comes into view (never on load). The G4 card shows it beside the success event, never in its place. A third client event lowered EVENT_DAILY_CEILING from 4,000 to 3,000 so the worst case stays at 12.6% of the account's D1 writes (cap 15%).

## 2026-11-12: daily snapshot of void news (T1, Studio stage 1)
void news keeps a cluster's deep dive only while it is printed, so each printed day is captured daily into R2 bucket `omnibus` under `snapshots/<printed date>/` (feed, weekly issue, outlet ratings, every printed cluster's deep dive, a sha256 manifest). Every file is read from void news's public repo at one commit resolved by `git ls-remote`: feed.json is not served on news.voidvision.org, one commit is one consistent printed state, and its blob URLs are the same provenance the normaliser already prints. Snapshots are keyed by the feed's printed date, not the capture time, because the edition landed after 12:00 UTC on 5 of the 7 days before this decision (11:52 to 21:12); so the bible's 12:00 run is kept and a 23:40 run catches a late edition, and a run that finds the same edition writes only the heartbeat. Trigger: a GitHub Actions cron (workflow 4, `snapshot`). No shared scheduler Worker exists on the account, and a Worker cron would spend one of the account's 5 triggers and parse about 2.5 MB of JSON against the free plan's 10 ms CPU limit. The Action needs the repo secret CLOUDFLARE_API_TOKEN (R2 edit); until it is set the capture is kept as a 90-day workflow artifact and the R2 step is skipped with a warning. Heartbeat: `GET /api/snapshots/heartbeat`, 503 once the last run is over 18 hours old. Sizes are capped (2 MiB a file, 8 MiB a day, the bucket at 3 GiB). The normaliser reads either source; its rules moved unchanged to `scripts/lib/normalise.mjs`, and the git source rebuilds `data/week-32.json` byte for byte.

## 2026-11-12: rights ledger, fetcher and dispute packet in Node (T2, Studio stage 8)
The bible names a Python local runner for stage 8, but the rights code is built in Node: the repo, its gate and CI are Node only, and the lints (`licence-allowlist`, `licence-evidence`, `ai-generated-share-zero`) must run in the gate on every push, so Python would add a second toolchain to CI or split one rule set across two languages. Node 22's `fetch`, streams and `crypto` cover the fetcher, so there are no new dependencies (the schema check is a small validator in `scripts/lib/rights/json-schema.mjs`, not a package). The future Python runner calls `node scripts/rights.mjs fetch <issue> --media <dir>` as a step. Each episode's `episodes/<issue>/rights-ledger.json` and its generated `disputes.json` are committed; media go to a directory outside the repo, and one inside it is refused. The schema is document's, with `licence_evidence` and `rights_checked` made structured (`docs/transplant-T2.md`).

Licence allowlist exactly per the bible: PD (US federal, by age, by explicit dedication), CC0, CC BY and BY-SA 1 to 4 (share-alike always, since episodes are CC BY-SA 4.0), EU reuse with the credit `© European Union, <year>`. AP, Reuters, Getty, AFP, logos, UN Web TV, Pexels, Pixabay and anything tagged AI-generated are refused whatever licence they claim. Bare "Public domain" and LoC's "No known restrictions" are not licences: an item needs a stated basis. The fetcher contacts only Commons, NASA Images, LoC and DVIDS hosts, checked on every redirect hop. Laundering heuristics for uploader claims: a capture date after the upload, or an own-work claim with no capture date, from an unreadable account, or from an account under 30 days old with under 50 edits, fails the item. DVIDS is optional: without `DVIDS_API_KEY` its candidates are skipped with a reason, and its field names are unverified against the live API until a key exists. The AI check is metadata only (categories, keywords, titles, descriptions, credits); `vision` stays `pending` until the stage 9 vision pass is built. In and out points stay empty in `disputes.json` until the render (T7) writes the master's edit list.

## 2026-11-12: rights review fixes (supersedes parts of the entry above)
On review of PR #6. NASA: an item is a federal work only when every credit it states is NASA's alone ("NASA", "NASA/<centre>", "NASA/<staff photographer>"), read from photographer, secondary_creator and credit statements in title, description and description_508; JPL counts as Caltech's, so "NASA/JPL-Caltech" fails, as do SpaceX, Boeing, MSSS, ESA and universities. LoC: public domain and a federal source must share one sentence, and any cautionary sentence ("may be protected", "copyright", "restricted", "not evaluated") refuses the item once LoC's standard link titles are set aside; pd-age is judged by the latest year stated, and applies only to publication 95 or more years ago or, with no contributor named, to creation 120 or more years ago. Commons: PD-old and its kin count only when the file's latest year is 95 years past (a US basis), and a "trademarked" or "insignia" restriction refuses the file. Outlets and networks (Al Jazeera, BBC, CNN, NBC, CBS, ABC News, Fox, Sky, DW, France 24, VOA and others) are denied by host, and by name in a credit; a name in a title is a subject and does not deny. AI marks are wider (more generators, AI-upscaled or colourised, deepfakes, a bare "AI" in a category, IPTC terms matched anywhere); generators whose names are ordinary words (Gemini, Flux, Firefly) count only after "generated by/with/using". The fetcher scans each file's first 256 KB for an XMP DigitalSourceType naming algorithmic media (refused) and a C2PA label (recorded, not judged). The lints re-read stored titles, credits, bases and captured text rather than trusting a recorded status. A plain dedication's packet cites the item's own evidence, never the CC0 deed. Still deferred, and not claimed anywhere: EXIF reading and reverse image search for laundering; paging Commons upload history past 20 revisions; a streaming cap on JSON bodies (they are read whole up to 4 MiB); an idle timeout on media downloads (only a total one); checking that a PD basis is stated in the captured evidence; verifying C2PA claims.
