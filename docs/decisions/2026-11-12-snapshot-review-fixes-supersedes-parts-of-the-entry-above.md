# 2026-11-12: snapshot review fixes (supersedes parts of the entry above)

On review of PR #4: the content hash no longer includes the void news commit (void news commits many times a day, and each commit forced a full re-upload); the commit stays as provenance on the manifest and on each file. A capture of the same edition (same printed time) now merges into what is stored and never drops a file, so a fresh runner's weaker 23:43 capture cannot erase the 12:17 one; only a later printed time replaces the day, and an earlier one changes nothing. R2 objects are named by content (`snapshots/<date>/blobs/<sha256>.json`): no object a live manifest names is ever overwritten, and superseded blobs are deleted only after the new manifest lands. Runs move to 12:17 and 23:43 UTC, off the busy minutes. The heartbeat goes stale at 30 hours, so one missed run does not page and two in a row do; it reports after the miss, so it says to fix the job, not that nothing was lost. verify-production checks the heartbeat and opens prod-red once the repo variable SNAPSHOT_R2_ENABLED is "true", which the coordinator sets after CLOUDFLARE_API_TOKEN is added and the release carrying the route is live. CLOUDFLARE_ACCOUNT_ID is a repo variable, not a secret. The git source can be pinned (`--at`), and a test rebuilds data/week-32.json byte for byte at its own commit.
