# 2026-11-22: T4, `bumper-no-bars` as a template-source assert; episode 900 as the graphics-only fixture (builder, from show bible v2 section i/o)

**bumper-no-bars.** Section i says the bias spectrum tokens "leave the graphics token file and live only in the site's token file." `design/tokens.css` is read by both the v1 and v2 generators (`render.STYLESHEETS["tokens_css"]`) and, as far as this builder could find, by nothing on the site side yet - splitting it now would mean standing up a second token file for the site with no site CSS importing it, while simultaneously risking the v1 board and day-bars rendering, which legitimately draw `--bias-*` for the lean ladder and must keep doing so (the frozen path). That refactor is bigger than one ticket's "first draft fast" licence, and nothing in the acceptance needs the tokens physically moved - only that the lint catches a bias token reaching an engine-drawn layer.

So the enforcer this ticket ships is `clean.assert_no_bias_tokens` (and its `find_spectrum_tokens`), the same shape as `clean.assert_clean`/`assert_no_internal_ids` already next to it: a pure string scan for `--bias-*`/`--spectrum-*` custom property names and the fourteen literal hex values those properties resolve to in `design/tokens.css` today (kept as a literal list, so the module stays I/O-free; a drift test is the honest way to catch the list going stale if `design/tokens.css`'s own hexes ever change). `render.Run.session` takes an opt-in `check_bias` flag, defaulting off (v1 keeps drawing bars), and every v2 renderer in `V2_RENDERERS` passes `check_bias=True`. The lint's entry in section o's table (`bumper-no-bars`) is ticket 6's to wire into the canary/text-lint machinery that reads a *screenplay*; this is the mechanism that actually stops a bias colour reaching a drawn layer's bytes, which is this ticket's own domain.

**Episode 900.** Ticket 4 ships before ticket 2's rundown/2 normaliser, so no real `episodes/35/screenplay.json` exists yet on `main` - the acceptance anticipates exactly this ("if none exists yet, render the fixture"). `fixtures.EPISODE_V2_FIXTURE` is a small, honest, clearly-marked non-episode (`issue: 900`, a number no real week will ever reach) exercising all four subtypes; `episodes/900/screenplay.json` is that dict dumped verbatim (checked by a test, so the two cannot drift), committed so `episode-draft.yml`'s `route` job's `test -f "episodes/$ISSUE/screenplay.json"` finds it. `episodes/900/graphics-ledger.json` is seeded as `[]`, because the workflow's graphics job copies the *committed* ledger aside before rendering, and a missing file would fail that `cp` before any render ran; the first dispatch's `verify.py compare` will therefore report every row as `only-fresh` (expected, not a bug) and the run's own ledger artifact becomes the real baseline for a follow-up commit, exactly as `episode-draft.yml`'s own comments already describe for any such baseline change.

`verify.py.release_args` is loosened to return `[]` (no `--release` flag) when a ledger carries no release-bearing row at all, rather than raising: issue 900's ledger has no clock entry, since `render_episode` does not draw one yet, and that is a legitimate shape, not an error (more than one distinct release time is still refused, unchanged).
