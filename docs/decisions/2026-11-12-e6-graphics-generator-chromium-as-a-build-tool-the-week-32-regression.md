# 2026-11-12: E6 graphics generator - Chromium as a build tool, the week-32 regression metric, and two net-new compositions

`studio/graphics/*` typesets the G2-approved HTML mocks (`design/mocks/broadcast/*.html`, `design/tokens.css`) into the episode's broadcast graphics, data-driven from `data/week-<n>.json` and `episodes/<n>/rundown.json`. One headless Chromium (Python Playwright, `studio/graphics/shoot.py`) renders each layer's STATIC, settled state only (`page.emulate_media(reduced_motion="reduce")`, matching frame.css's own `prefers-reduced-motion` rule and spec 1.3's "the broadcast mocks were captured with reduced motion on"); every motion preset (flap, wipe, step, sweep, credits roll, the typed-paper reveal) is then built in numpy/PIL (`compose.py`) from that static PNG, never played out as a CSS animation on screen. This mirrors E5b's precedent (`scripts/capture_page.py`) and is a **build tool invoked by a script** (`python -m studio.graphics.render`), not the agent's own interactive browser: CLAUDE.md's "Playwright is allowed only for the verifier and the user-sim" rule governs that tool, not an unattended render process. One browser instance per run, closed on exit even on error (`shoot.chromium()`'s context manager).

**Geometry, reverse-derived.** `layout.py` and `svgparts.py` rebuild the mocks' own static geometry from formulas (bar-segment widths, the key's 7 equal columns, the ladder's 15 ticks and 7 rung centres, a board row's drift margin and an outlet's clamp, the clock's 60 ticks and its hour/minute/second hand angles, the castellated border, the fine grid) rather than copying their baked numbers, each checked in `studio/tests/test_graphics_{layout,svgparts}.py` against the literal pixel values already committed in the week-32 mocks.

**Week-32 regression (E6 acceptance).** `studio/graphics/render.py regression32` shoots each generator layer and its matching mock (navigated in place via `shoot.shoot_path`, so the mock's relative stylesheet links resolve) and reports the mean absolute per-channel pixel difference (0..255): testcard-week 0.0, testcard-echo 0.0, clock 0.0, flap-board 0.068, count-card 0.186, lower-third 0.437, end-board 0.467 (`D:/omnibus-media/33/graphics/regression-32/pixel-diff.json`). **Corrected on review (below): that first run did show layout defects, and its claim of none was false.** `fixtures.py`'s *copy* (board headlines, the count card's context sentence) is transcribed from the committed mocks themselves, since week 32 predates `episodes/32/rundown.json`; its *numbers* are cross-checked against `data/week-32.json` directly in `studio/tests/test_graphics_fixtures.py` (the board rows against `lead.board`, sha256 included).

**Two compositions with no G2 mock.** (1) Day lean bars (`studio/graphics/typeset.py day_bars_html`): the-week's per-day device (`rundown.json` parts[].beats[].device.kind == "day-bars") has no dedicated mock; it reuses the approved bar/caption/slate grammar at a smaller scale, never a new colour or face. (2) A multi-row count card (cw-1's three claim terms, cw-4's Kefauver/Truman comparison): `count-card.html` only ever shows one hero numeral; `count_card_html` keeps that exact layout (300/350/600/760px) for a single row and, for more than one, distributes rows evenly in a smaller face (≤132px) so numerals and context lines never overlap - an early version at a flat per-row offset did overlap, caught by eye before this file was written and fixed before the week-33 render below.

**Week-33 render.** 25 graphics (4 test cards, a 2-page board, 3 lower thirds joined from `the-echo`'s beats against `echo-pick.json`'s `period_perspectives` by source id, 4 count cards including cw-1's Iran 39 / Israel 4 / inflation 1 of 46, 7 day-bars, the clock's dial and hands as separate ProRes layers, one credits strip, the end board, and the title's 14-row typed-paper macro at the declared 74.3 cps), all ProRes 4444 (`yuva444p12le`) at D:/omnibus-media/33/graphics/, 707 MB, D: left at 58 GB free; `episodes/33/graphics-ledger.json` (25 rows, class DRAWN throughout). counts-match reads every test-card bar and count-card hero back from its own `data-rung`/`data-row` attribute (not CSS positional selectors, which broke E8's naive `nth-of-type` guess by counting all SVG `<text>` siblings, not just the counted ones) and asserts it against the data before the frame is kept. graphics-clean (`clean.py`) scans every generated layer's markup for scanline, noise, vignette, curvature and interlace before it is shot; none appeared.
