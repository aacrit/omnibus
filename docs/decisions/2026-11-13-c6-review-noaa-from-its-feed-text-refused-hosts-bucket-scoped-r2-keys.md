# 2026-11-13: C6 review: NOAA from its feed text, refused hosts, bucket-scoped R2 keys

On review of cap/c6-c7. A NOAA item is judged from its RSS item's own text (`gov.parseFederalPage` on `item_html`), which is the page evidence kept; no NOAA page is asked, and its terms page (on the same refused host) is stated missing, so the evidence lint refuses its media: metadata and evidence only. No page, adapter lookup or proxy asks a host C0 recorded as refusing (`isRefusedHost`), and a host that answers 403 during a run is not asked again in that run. CoS decision: the capture reaches R2 through its S3 API with an R2 API token scoped to the buckets `omnibus-capture` and `omnibus` (secrets `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_ACCOUNT_ID`, the names C8 shares), signed by a dependency-free SigV4 signer (`scripts/lib/r2-s3.mjs`, checked against AWS's published example), instead of an account-wide `CLOUDFLARE_API_TOKEN`; the code writes only `omnibus-capture` and reads `omnibus` through a read-only view (an R2 token carries one permission for every bucket it names). A laptop without the secrets falls back to `wrangler login`. Founder's steps: Cloudflare dashboard, R2, Manage API tokens, Create API token, Object Read & Write, Specify buckets `omnibus-capture` and `omnibus`; copy the Access Key ID, Secret Access Key and account id into the three repo secrets.
